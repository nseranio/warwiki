# Dependency upgrade and compiled-site validation

The coordinated upgrade removes all four critical audit entries and reduces the audit from 63 package entries (4 critical, 37 high, 19 moderate, 3 low) to **17 high entries, zero critical/moderate/low**. The remaining entries are one unpatched `image-size` dependency plus 16 Docusaurus parent entries that inherit it. These are dependency advisories, not a count of independently exploitable site flaws. Raw snapshots: `dependency-audit.json` and `dependency-audit-after.json`.

## Changes

- All six Docusaurus packages move together from 3.10.0 to 3.10.2; Sharp moves to 0.35.4. Vitest moves from 2 to the maintained/patched 4.1.11 line with Vite 7.3.6 and the matching React Vite plugin. The project targets Node 24 LTS via `engines.node: 24.x` and `.nvmrc`, matching the tested local major. Vercel honors this package engine on the next deployment; its Node 20 deprecation is October 1, 2026. CI must use Node 24 too. [Vercel Node 20 deprecation](https://vercel.com/changelog/node-js-20-is-being-deprecated), [Node LTS status](https://nodejs.org/en/about/previous-releases). [Docusaurus release](https://github.com/facebook/docusaurus/releases/tag/v3.10.2), [Sharp release](https://sharp.pixelplumbing.com/changelog/v0.35.4/), [Vitest 4 documentation](https://v4.vitest.dev/)
- Removed the project dependency on `@vercel/node`, which was used solely for two TypeScript types while installing a full deployment builder and vulnerable transitive packages. The speech handler now uses native Node request/response types and retains Vercel's supported Node handler contract and parsed request body. It still defaults to disabled paid speech. This does not replace or pin Vercel's platform-managed builder. [Vercel Node runtime](https://vercel.com/docs/functions/runtimes/node-js)
- Applied normal compatible transitive updates. Four scoped overrides close pinned advisories: `serialize-javascript@7.1.1` for Copy/CSS Minimizer plugins, `qs@6.16.0` for Express, and `uuid@11.1.1` for SockJS. Serializer's major change is its Node 20 minimum, already required here; tests cover the serialization shapes used by the build. SockJS uses only the zero-argument CommonJS `v4()` API, still supported by UUID 11. [Serializer compatibility](https://github.com/yahoo/serialize-javascript/releases/tag/v7.0.0), [patched serializer release](https://github.com/yahoo/serialize-javascript/releases/tag/v7.1.1), [UUID 11 API](https://github.com/uuidjs/uuid/blob/v11.1.1/README.md), [qs change log](https://github.com/ljharb/qs/blob/v6.16.0/CHANGELOG.md)
- Added explicit Node and React DOM types and `parse5` for the build-output checker. No forced audit fix, unsupported Docusaurus downgrade, or paid API call was used.

## Remaining upstream issue and temporary mitigation

The published latest `image-size` is 2.0.2, also used by Docusaurus 3.10.2. It has unresolved infinite-loop advisories for malformed ICNS and JPEG XL / HEIF inputs; no patched version is listed. Because the site is built to static files, these image decoders are build-time tooling, not a public image-upload service. [ICNS advisory](https://github.com/advisories/GHSA-w3rx-r6r6-pgpr), [JPEG XL / HEIF advisory](https://github.com/advisories/GHSA-5p2g-fcmc-qvqq)

A new guard reads only short file headers, without image decoding, across `static`, `docs`, and `src` before normal `npm run build` or `npm start`. It rejects ICNS/JXL/HEIF/HEIC/AVIF extensions and their recognized binary signatures, including files disguised as JPEGs. Current source inputs pass. This reduces the known input exposure in the normal build path; it is not a library patch, does not erase the audit warning, and direct manual Docusaurus invocation can bypass the wrapper. Keep the advisory visible and remove this temporary restriction only after a supported upstream fix is installed and tested. Fixture tests cover disguised signatures and permitted existing formats.

## Compiled-site checks

The new postbuild checker parses every generated HTML file, checks local routes, fragment IDs, styles/scripts/image/media assets, same-site absolute URLs, and static local route literals in documentation and database data. It includes tabs/filter datasets that may not appear in the initial server render. Computed JavaScript destinations are not fully provable with this literal scan; targeted component tests remain useful.

The initial scan covered 1,191 HTML files, 100,375 rendered local links/assets and 731 source data-link literals. It found four failures at three unique destinations: two headings whose embedded Skills badges changed their generated anchor, and an incorrect Dartos RUF reference fragment. The headings now have stable explicit IDs. The RUF citation now points to the verified five-patient Dafnis 2024 modified York–Mason report, rather than the unrelated reference 11; its uncontrolled series design is explicit. [Dafnis primary abstract](https://pubmed.ncbi.nlm.nih.gov/38834146/)

## Verification

A clean `npm ci` succeeded. An isolated Docusaurus production build exercised image copying and CSS minification after the serializer overrides. Dependency compatibility, speech endpoint, image guard and compiled-route fixtures passed, alongside the site's component/type checks. The final full-site production build now passes after the parallel editorial and figure changes: 1,192 HTML pages, 102,789 local links/assets and 746 data-link literals, with zero missing routes/assets/anchors. The output is 139,552,607 bytes (139.55 MB) and passes the enforced 200 MB postbuild budget. Final suites pass 38 component/API tests and 42 maintenance tests; typecheck also passes. Full machine-readable results are in `rendered-link-validation.json` and `build-size-after.json`.

The source-only reference and media maintenance reports are separate authoring artifacts. They are not imported into the browser bundle.
